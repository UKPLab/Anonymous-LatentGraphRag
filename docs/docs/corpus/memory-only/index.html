Memory-Only

Single tree over the relational-memory index. Each retrieved memory carries provenance back to its source document. Best on width-oriented FanOutQA (31.45 R@5), where many small facts assemble into one answer.

Memory-only tree. Memories are verbalized triples; scores project back to source documents at the end.

Parameters

NameTypeDefaultDescription
corpus"memory_only"—Search only the relational-memory index.
searchSearchStrategy"full_expansion"Single-view strategies only.
branchingint | "adaptive"3Top-b memories per hop.
max_hopsint4Maximum retrieval depth.

Projection to documents

Memory paths are projected back to source documents at the end. EachRelationalMemory carries a doc_id; the projection takes the max score per source document.

When to use

  • Width-oriented tasks where many distinct facts contribute (FanOutQA-style).
  • Diagnostic: comparing memory-only vs document-only isolates how useful the extracted relations are.
  • You want a smaller search space than the full chunk index.
