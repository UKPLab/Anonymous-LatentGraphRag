Tutorial 3: Encode

Encoding is the bridge between text and the latent graph. In step 2, rag.build_graph(...) ran the encoder twice — once over chunks and once over verbalized memories. This step explains what happened and how to control it.

RoleInstruction
Document"Represent the document: "

Vectors are L2-normalized so inner-product equals cosine similarity.

Why multi-hop matters

At each retrieval hop, the query context grows: c_t = [q; x_1; …; x_{t-1}]. The encoder has to keep producing useful similarity signal over that growing prompt. A generic sentence-similarity model trained on short snippets won't do this well — it hasn't seen this regime in training. The bundled encoders (GritHopper, NV-Embed-v2, the OpenAI embeddings family) all handle it; a custom encoder needs to too.

Available encoders

  • GritHopperEncoder — the default, multi-hop trained, requires pip install latentgraphrag[gritlm]
  • OpenAIEncoder — OpenAI / OpenAI-compatible API embeddings (text-embedding-3-large by default)
  • NVEmbedV2Encoder — NV-Embed-v2

See API → Encoders for the full reference.

A custom multi-hop encoder

BaseEncoder is a tiny ABC; any class that implements encode(texts, *, instruction=None, is_query=False) -> np.ndarray plugs in. The important part is that your encode does something different for queries vs documents — that's what makes multi-hop work.
