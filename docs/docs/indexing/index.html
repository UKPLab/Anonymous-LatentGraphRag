Index a corpus, save, reuse

This page goes from a document corpus to a ranking that seeds the ReAct agent, with every intermediate result on disk: the constructed knowledge as memories.jsonl, the encoded index as a directory. Encoding runs once per corpus; afterwards the index is loaded and searched without encoding the corpus again.

1. The corpus

The corpus is a dict {document id: text}. Ids are strings or integers (a saved index stores them as JSON); every ranking the package returns is a list of these ids.

python
import json

documents = {}                                   # {document id: text}
with open("corpus.jsonl") as f:
    for line in f:
        record = json.loads(line)
        documents[record["id"]] = record["text"]

# chunked corpus: one entry per chunk, and the document id of each
chunks = {"d1#0": "…", "d1#1": "…", "d2#0": "…"}
groups = ["d1", "d1", "d2"]     # lgr.build(chunks, ..., groups=groups)

A chunked corpus keeps one entry per chunk and passes groups, the document id of every chunk in order, to lgr.build. A document's score is then the maximum over its chunks among the readout's top units, and memory sources must be the document ids in groups. See Retrieval.

2. Constructed knowledge

Memories are triples and propositions, each with the list of documents it was extracted from (π). They are either extracted here or loaded from existing extraction output.

Extract

triples.extract_with_hipporag runs HippoRAG's OpenIE, propositions.extract_with_proprag runs PropRAG's own extraction; both call an OpenAI-compatible endpoint and cache the LLM calls in save_dir. Passing {document id: text} makes each record's idx the document id, so from_openie and from_records need no mapping.

python
from latentgraphrag import propositions, triples

# triples: HippoRAG's OpenIE (pip install -e ".[construction]")
tri_records = triples.extract_with_hipporag(
    documents, llm_name="Qwen/Qwen3-Next-80B-A3B-Instruct",
    llm_base_url="http://localhost:8000/v1", save_dir="openie_cache")

# propositions: PropRAG's own extraction, from a local PropRAG checkout
prop_records = propositions.extract_with_proprag(
    documents, llm_name="Qwen/Qwen3.5-27B",
    llm_base_url="http://localhost:8001/v1", save_dir="proprag_cache",
    proprag_root="path/to/PropRAG")

# each record's idx is the document id it was extracted from
tri = triples.from_openie(tri_records)
pro = propositions.from_records(prop_records)

PropRAG is not installed by any extra: proprag_root is the root of a local checkout. The model names above are the ones the paper used for FanOutQA and BrowseComp+; any served model works. Details are on the Knowledge construction page.

Or load existing output

HippoRAG-format OpenIE files and PropRAG output key their records by chunk id, "chunk-" + md5(title + "\n" + text). chunk_id(title, text) computes it, and source_of maps it to your document ids; records it does not know are skipped.

python
from latentgraphrag import chunk_id, propositions, triples

# outputs keyed by chunk id, e.g. the HippoRAG 2 / PropRAG releases
chunk_to_doc = {chunk_id(title, text): doc_id
                for doc_id, (title, text) in titled_passages.items()}
openie = triples.load_openie("openie_results.json")
tri = triples.from_openie(openie, source_of=chunk_to_doc)
records = propositions.load_records("proprag_openie.json")
pro = propositions.from_records(records, source_of=chunk_to_doc)

One inventory, saved

MemoryInventory.union puts both kinds into one memory index and merges the provenance of memories that occur in several documents. Save it once; extraction does not have to run again.

python
from latentgraphrag import MemoryInventory

inventory = MemoryInventory.union(tri, pro)  # provenance merged
inventory.stats()      # counts: memories, triple, proposition, sources
inventory.save_jsonl("memories.jsonl")
inventory = MemoryInventory.load_jsonl("memories.jsonl")

triples_only = inventory.select("triple")         # or "proposition"

memories.jsonl holds one record per memory; sources are document ids:

memories.jsonl
{"text": "Erik Jensen was born in Appleton.", "sources": ["musique_008960"], "kind": "triple"}
{"text": "Erik Jensen was born on October 11, 1980, in Appleton, Wisconsin.", "sources": ["musique_008960"], "kind": "proposition"}

inventory.select("triple") or select("proposition") builds a documents + triples or documents + propositions index from the same file.

3. Encode once and save

lgr.build encodes the documents and the memory texts with the RDR checkpoint and returns an LGRIndex; index.save writes it to a directory.

python
from latentgraphrag import PAPER, LatentGraphRAG

lgr = LatentGraphRAG("path/to/rdr-checkpoint", config=PAPER)
index = lgr.build(documents, inventory,
                  cache_dir="cache/my-corpus")  # chunked: groups=groups
index.save("lgr_index")

cache_dir writes the embeddings to cache_dir/documents and cache_dir/memories while encoding; a later build with the same cache_dir loads them instead of encoding again. The cache is not checked against the texts or the model, so use one directory per corpus and checkpoint. Without an inventory, lgr.build(documents) builds a documents-only index.

The saved index

lgr_index/
lgr_index/
├── lgr_index.json      format, document ids, doc_of, whether memories exist
├── inventory.jsonl     one {"text", "sources", "kind"} record per memory
├── documents/          RDR index over the documents (or chunks)
│   ├── embeddings.npy  float16, one row per entry
│   ├── index.json      ids, groups, n, dim
│   └── texts.jsonl     the texts, one JSON string per line
└── memories/           RDR index over the memory texts, same files

Embeddings are stored as float16. documents/ and memories/ are plain RDR indices (rdr.DenseIndex.save), so RDR can load each of them on its own.

4. Load and search

Later, in another process, create the retriever with the same checkpoint and load the directory. load_index puts the vectors on the retriever's index device; LGRIndex.load(path, device=None, dtype=None) chooses device and dtype explicitly (default: float16 on GPU, float32 on CPU).

python
from latentgraphrag import PAPER, LatentGraphRAG

lgr = LatentGraphRAG("path/to/rdr-checkpoint", config=PAPER)
index = lgr.load_index("lgr_index")      # nothing is encoded again

results = lgr.search(questions, index, k=10)   # one result per question
result = results[0]
result.ranking        # [(doc id, score), ...], best first
result.ids            # the document ids alone
result.views["D"]     # document view, {doc id: score}
result.views["M"]     # memory view projected to documents

documents_only = lgr.search(questions, index, k=10, view="D")

search takes a batch of questions and returns one LGRResult per question. Only the query states are encoded at search time. view="D" is the documents-only configuration; the other views ("M", "J", "D+J") are on the Retrieval page.

5. Seed the ReAct agent

The top ten documents of a ranking become the agent's initial evidence. The agent then searches on its own, with a separate, plain embedding index over the same documents: DenseSearchTool(embeddings, texts, ids=None, query_encoder=None, k=5, text_cap=2000, log_top=1000).

python
import numpy as np
from latentgraphrag import (
    BrowseCompGrader, DenseSearchTool, OpenAIChatModel, ReActAgent, Seed)

# the agent's own search index: plain embeddings, stored once as .npy
ids = list(documents)
emb = np.load("agent_index/embeddings.npy")   # (N, d), order of ids
tool = DenseSearchTool(emb, [documents[d] for d in ids], ids)
llm = OpenAIChatModel(model="Qwen/Qwen3.5-122B-A10B",
                      base_url="http://localhost:8000/v1")
agent = ReActAgent(llm, tool)                     # at most 10 searches
grader = BrowseCompGrader(llm)

for question, result, gold in zip(questions, results, answers):
    seed = Seed.from_ranking(result.ids, documents)   # top 10
    trajectory = agent.run(question, seed)
    verdict = grader.grade(question, trajectory.output, gold)
    print(trajectory.tool_calls, trajectory.final_answer, verdict.correct)

The tool scores documents by the dot product with the query vector. Its default query encoder, Qwen3QueryEncoder, is Qwen3-Embedding-8B with last-token pooling and no instruction, so the document embeddings must be L2-normalised embeddings of the same model, in the order of ids. The package does not encode them; for example, with sentence-transformers:

python
import numpy as np
# sentence-transformers is not a dependency of latentgraphrag
from sentence_transformers import SentenceTransformer

encoder = SentenceTransformer("Qwen/Qwen3-Embedding-8B")
emb = encoder.encode([documents[d] for d in ids], normalize_embeddings=True)
np.save("agent_index/embeddings.npy", emb)

Another encoder works as well when its query side is passed as query_encoder (any str -> (d,) vector). To keep the trajectories, trajectory.to_runner_row(...) gives the row layout of the paper's run files. The agent loop, its parameters and the prompts are on the ReAct agent page.
