Latent graph

The central idea: instead of traversing a static knowledge graph at query time, let the encoder define the graph. At hop t, the recursive query-state embedding of the question together with what has already been retrieved induces an implicit edge to every candidate in the corpus, weighted by cosine similarity.

A retrieval path ⟨x₁, …, x_t⟩ is a path in this query-conditioned latent graph: an edge from the current context to a candidate exists when the encoder assigns it high similarity. Edges are never materialized — they're defined implicitly by the encoder's similarity geometry, every retrieval step.

Why "latent"?

The edges in this graph are never materialized. They're defined implicitly by the encoder's similarity geometry — every candidate is potentially connected to every context, with the connection's strength determined at retrieval time.

This contrasts sharply with traditional graph-based RAG, which treats the extracted knowledge graph as the retrieval substrate: edges are fixed at indexing time, and the retriever traverses them. Latent edges, in contrast, adapt to the query.

What the latent graph buys you

  • No decomposition needed. The encoder learns to focus on what's still missing given what's been retrieved; no separate question-decomposition LLM call.
  • Robust to incomplete extraction. If OpenIE missed a key relation, the latent graph can still surface the right document via dense similarity to the context.
  • Composable. The same primitive works whether you index documents, memories, or both — exactly because edges aren't pre-baked.

Connection to search strategies

The latent-graph view also clarifies what each search strategy is:

  • Full expansion explores the entire b-ary subtree of the latent graph up to depth H.
  • BeamDR keeps only the top-B paths by cumulative score at each hop — a pruned BFS on the latent graph.
  • Cross-view beam traverses two latent graphs (documents and memories) jointly, keeping a single beam across both.

All five search strategies are just different traversal policies on the same latent graph. See the Search Strategies pages for the animated walkthrough of each.
