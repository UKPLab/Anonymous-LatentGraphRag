Or build with vLLM (self-hosted, batched, prefix-cached)

For larger corpora you don't want to pay per-API-call latency or rate limits. Self-host an OpenIE LLM with vLLM and LatentGraphRAG will batch the entire NER pass and the entire triple-extraction pass — the few-shot prompt prefix is shared across all chunks, so prefix caching turns the demonstration tokens into a one-time cost.

The same VLLMOffline instance handles both NER and triple extraction. Indexing scales roughly linearly with corpus size; doubling the corpus doubles the wall-clock time rather than the per-call latency.

What just happened

The build_graph call ran a four-stage pipeline:

  1. Chunking — TokenChunker split each document at the 512-token mark (with 50 tokens of overlap). Tiny documents like ours become one chunk each.
  2. OpenIE — gpt-4o-mini extracted named entities and (subject, relation, object) triples per chunk. Cached to ./my_corpus/openie_cache.json.
  3. Verbalization — every triple (h, r, t) was rewritten as a single natural-language sentence ("Alice lives in Paris.") and stored as a RelationalMemory.
  4. Graph build — chunk, entity, and memory nodes were added to an igraph, connected by chunk_entity, chunk_memory, and entity_relation edges.
