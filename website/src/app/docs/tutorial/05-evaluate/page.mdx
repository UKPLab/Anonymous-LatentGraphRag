# Tutorial 5: Evaluate

The headline retrieval metric is **Recall@K** — fraction of gold supporting documents
that appear in the top-K retrieved. The package ships `recall_at_k`, `qa_exact_match`,
and `qa_f1` for the standard evaluation loop.

## A tiny labeled set

For the mini corpus, we&apos;ll annotate two questions with their gold doc ids. In
practice you&apos;d use the dataset&apos;s provided gold annotations.

```python title="eval_set.py"
QUESTIONS = [
    "Where does Alice live?",
    "Who works in Berlin?",
]
GOLD = [
    ["doc-of-alice"],   # both questions about Alice resolve to the same doc
    ["doc-of-bob"],
]
```

> The exact `doc_id`s come from your `build_graph` run — they&apos;re MD5 hashes of
> the source document text, prefixed with `"doc-"`. You can inspect them via
> `rag.store.nodes_of_kind("chunk")` and walking back to `doc_id` attributes.

## Compute Recall@5

```python title="evaluate.py"
import latentgraphrag as lgr
from latentgraphrag.evaluation import recall_at_k

rag = lgr.LatentGraphRAG.load("./my_corpus")

results = rag.retrieve(
    QUESTIONS,
    corpus="dual_tree",
    search="full_expansion",
    fusion="agreement",
    branching_doc=3,
    branching_memory=5,
    max_hops=4,
    k=10,
    gamma=0.0,
)
retrieved = [r.documents for r in results]
print(f"Recall@5  : {recall_at_k(retrieved, GOLD, k=5):.3f}")
print(f"Recall@10 : {recall_at_k(retrieved, GOLD, k=10):.3f}")
```

`recall_at_k` is macro-averaged: per query, fraction of gold docs in the top-K; then
mean across queries.

## Sweep configurations

A full ablation grid is just a loop — the orthogonal axes make this cheap:

```python title="ablation_grid.py"
configs = {
    "doc-only":       dict(corpus="document_only", search="full_expansion", branching=3),
    "memory-only":    dict(corpus="memory_only",   search="full_expansion", branching=3),
    "joint-index":    dict(corpus="joint_index",   search="full_expansion", branching=5),
    "dual / RRF":     dict(corpus="dual_tree",     search="full_expansion",
                           fusion="rrf", branching_doc=3, branching_memory=5),
    "dual / agree":   dict(corpus="dual_tree",     search="full_expansion",
                           fusion="agreement", branching_doc=3, branching_memory=5),
    "cross-view":     dict(corpus="dual_tree",     search="cross_view_beam", beam_width=10),
}

for label, kw in configs.items():
    results = rag.retrieve(QUESTIONS, max_hops=4, k=10, **kw)
    retrieved = [r.documents for r in results]
    r5  = recall_at_k(retrieved, GOLD, k=5)
    r10 = recall_at_k(retrieved, GOLD, k=10)
    print(f"{label:14s}  R@5={r5:.3f}  R@10={r10:.3f}")
```

You&apos;ve now produced a full ablation grid on your own data — every row of the
configuration matrix in one loop.

## QA evaluation (optional)

If you&apos;re running an end-to-end QA evaluation (rather than just retrieval), the
package also exposes EM and F1:

```python title="qa_metrics.py"
from latentgraphrag.evaluation import qa_exact_match, qa_f1

prediction = "Paris"
gold = ["Paris, France", "the city of Paris"]

print(f"EM : {qa_exact_match(prediction, gold):.0f}")  # 0 or 1
print(f"F1 : {qa_f1(prediction, gold):.3f}")           # 0..1
```

Both functions handle the standard SQuAD-style normalization (lowercase, strip
articles, strip punctuation, whitespace-tokenize).
