Why LatentGraphRAG?

Knowledge-graph-based RAG systems traditionally traverse an extracted graph at query time, propagating across fixed edges. LatentGraphRAG takes a different view: it treats every graph-derived edge as a relational memory — a verbalized natural-language sentence — and retrieves those memories with the same iterative recursive dense retrieval used for documents.

The benefit is unification: the same retrieval primitive handles documents, memories, joint indices, and dual trees. Search strategies and fusion methods compose orthogonally with the corpus choice, giving you a clean matrix of configurations to mix and match.

At a glance

  • Drop-in API — one class, three methods: build_graph(), retrieve(), save() / load().
  • Four corpus modes × six search strategies × two fusion methods — every combination is one keyword away.
  • FAISS-accelerated ANN search with CPU and GPU backends; falls back to numpy brute-force when FAISS isn't installed.
  • Modular encoders — GritHopper by default; implement BaseEncoder for a custom multi-hop-capable encoder.
