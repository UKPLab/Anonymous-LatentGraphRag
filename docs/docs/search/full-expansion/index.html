Full Expansion

At every hop, every state expands into its top-b children. After H hops you have up to bH paths through the latent graph, ranked by cumulative score. The most robust strategy out-of-distribution.

Algorithm

frontier = [Path()]
all_paths = []
for hop in range(max_hops):
    contexts = [build_context(query, p) for p in frontier]
    ctx_vecs = encoder.encode(contexts, is_query=True)
    scores, idx = index.search(ctx_vecs, k=branching)
    next_frontier = []
    for fi, path in enumerate(frontier):
        for j in pick(scores[fi], idx[fi], branching):
            next_frontier.append(path.with_extension(item_j))
    all_paths.extend(next_frontier)
    frontier = next_frontier

return sorted(all_paths, key=lambda p: p.cumulative_score, reverse=True)[:k]

Why it's the robust default

Full expansion never prunes a state based on a single hop's score. In out-of-distribution settings (BrowseComp+), early hop scores are poorly calibrated; BeamDR may drop the correct path early. Full expansion keeps every path alive at the cost of more compute (bH states).

When to use branching="adaptive"

Adaptive branching expands a state only while the score margin between consecutive candidates stays within branching_threshold. It self-tunes the fanout: wide on confident hops, narrow on uncertain ones. When to reach for it:

  • Recommended: corpus="document_only", search="full_expansion", branching="adaptive" on out-of-distribution / web-scale corpora (BrowseComp+-style). Encoder scores are flat and poorly calibrated there; fixed b=3 either over-explores cheap dead ends or under-explores the right neighborhood. Adaptive lets the threshold do the work.
  • Less useful on clean datasets (MuSiQue-style). Scores are calibrated enough that fixed b=3 already finds the right next step every hop; adaptive adds variance without much gain.
  • Tuning hint: start with branching_threshold=0.05. Increase (e.g. 0.10) if the search misses obvious neighbors, decrease (0.02) if it's exploring too aggressively.

On in-distribution / depth-oriented tasks, the integer-branching defaults usually win. Both options ship in v0.1 precisely because they fail in opposite regimes — pick whichever matches your data's score calibration.
