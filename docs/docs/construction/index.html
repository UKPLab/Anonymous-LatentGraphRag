Knowledge construction

LatentGraphRAG reuses the knowledge that graph-based retrievers construct: triples from open information extraction and propositions. It does not traverse a graph built from them. Each constructed unit becomes a memory: a short text plus the list of source documents it was extracted from (its provenance π). The memory tree searches the texts; the provenance maps memory scores back to documents.

Constructed knowledge enters the package through latentgraphrag.construction and is held in a MemoryInventory.

Whitespace is collapsed, a final period is appended if missing, and a triple that is empty after normalisation is skipped. Malformed triples (not three elements) are skipped when reading OpenIE records.

From an OpenIE file

triples.load_openie(path) reads a HippoRAG-format OpenIE cache: the JSON form {"docs": [...]} or JSON lines, either optionally gzipped. Each record carries the chunk id idx and its extracted_triples.

source_of maps a record's idx to the document id used by the document index. It can be a mapping or a callable; records it does not know are skipped. Without it, the idx itself is the document id.

Extraction with HippoRAG

triples.extract_with_hipporag runs HippoRAG's OpenIE (named entities, then triples) over {chunk id: passage} against an OpenAI-compatible endpoint and returns records ready for from_openie. HippoRAG is MIT licensed; install it with the construction extra, or pass the src directory of a checkout as hipporag_src. HippoRAG caches its LLM calls in save_dir.

Propositions

A proposition is a self-contained statement extracted from one passage. The paper uses PropRAG's propositions.

Each record carries idx and a list of propositions (strings, or objects with a text field). Empty propositions are skipped.

Extraction with PropRAG

propositions.extract_with_proprag runs PropRAG's own extraction (entities, then propositions, with its prompts and output repair) from a local PropRAG checkout. PropRAG is not bundled, because its repository ships without a license file; this package calls it and does not copy its prompts.

Memory inventories

How an inventory is built from a corpus, saved and indexed is walked through step by step on Index a corpus, save, reuse.

MemoryInventory holds unique memory texts, their source ids and their kind ("triple" or "proposition"). A memory extracted from several documents has several sources.

union keeps memories in order of first appearance and merges the provenance of a memory that occurs in several inputs. Triples and propositions in one inventory form one memory index, as in the paper's full configuration.

Sources must be document ids

The sources of an inventory must be the ids the document index uses: the keys of the documents passed to LatentGraphRAG.build, or, for a chunked corpus, the document ids given in groups. The projection uses the source ids as given, so ids that differ from the index's (for example chunk ids instead of document ids) put the memory view on different ids than the document view, and the two views no longer fuse.
