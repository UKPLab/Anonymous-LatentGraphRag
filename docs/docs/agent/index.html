ReAct agent

In retrieval-first seeding, a retriever's ranking becomes the initial evidence of a ReAct agent: the top ten documents are shown before the agent's first turn, and the agent may then search on its own. The seed is not a search call and does not count against the search budget. latentgraphrag.agent is a port of the runner behind the paper's agent experiments (agent results).

The demo below replays three released trajectories of the paper's agent, one per problem type: the seed, every SEARCH the agent issued with the five documents it returned, and the graded final answer.

Seeds

A Seed is an ordered list of documents, each with its text and, when known, its id.

ConstructorDescription
Seed.from_ranking(ranking, texts, k=10, text_cap=2200)top k of a ranking of document ids; texts maps id to text
Seed.from_texts(texts, ids=None, k=10, text_cap=2200)from texts already in rank order
Seed.empty()no initial evidence (the unseeded condition)

Texts are cut to text_cap characters (None keeps them whole). from_ranking takes document ids; for a LatentGraphRAG result pass result.ids, not result.ranking, which holds (id, score) pairs. Any ranking works as a seed, so the same agent compares retrievers by swapping only the seed.

The agent loop

Each turn the controller generates greedily and ends with one action line: a search (SEARCH: <query>) or a final answer (Exact Answer: <answer>).

  • A search runs the search tool while searches remain; the results come back as the next user turn.
  • The observation after the last allowed search asks for the final answer.
  • A turn without a valid action (for example, cut at the token limit) receives exactly one follow-up request for a single action line, capped at followup_max_tokens.
  • If a prompt exceeds the context window, the call is retried once with the largest max_tokens that still fits (at least 1,024 tokens). If it still fails, earlier search results are shortened step by step and the call is repeated (fit_context=True).

seed_placement decides where the seed appears. "documents" (the main protocol) puts it as numbered documents in the first user turn. "search_turn" presents it as the result of a simulated first search with the question as query; that search is not counted.

The prompt texts are shown in the paper (Figures 3 and 4) and live in latentgraphrag/agent/prompts.py.

Search tools

A search tool implements two methods: start(question, seed) returns a SearchContext for the episode, and search(query, context) returns a SearchResult with the hits shown to the agent and the logged top of the live ranking.

DenseSearchTool is the paper's tool: plain embedding search over a fixed index. The query is encoded, scored against the document embeddings by dot product, and the top k documents are returned without any filtering of documents seen before.

embeddings are precomputed, L2-normalized document embeddings of shape (N, d); texts are the N document texts and ids their ids (default: positions). The default query_encoder is Qwen3QueryEncoder, loaded on the first search: Qwen3-Embedding-8B with last-token pooling, no instruction, the query cut to 512 characters and 512 tokens. Any callable str -> (d,) vector can replace it, provided it matches the encoder of embeddings.

RankFileFusedSearchTool is the fused-tool ablation. For every agent query it fuses the live ranking with a fixed ranking of the current question by reciprocal rank fusion, skips documents already shown in the episode (seed and earlier results), and returns the top k.

rank_lists maps a question (whitespace-collapsed, lower-cased) to index positions of base, best first. position_of maps seed document ids to index positions so seed documents count as shown; with match_seed_text, seed documents without a known id are matched by their text.

Chat models

The agent, the reader and the grader use any object with a chat method:

ChatResult holds text, an optional separate reasoning, finish_reason and token counts. Errors are raised as exceptions; an exceeded context window is recognised by the server's message.

enable_thinking is passed as chat_template_kwargs.enable_thinking; the paper runs with reasoning disabled. The client makes no hidden retries.
