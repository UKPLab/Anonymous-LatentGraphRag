Retrieval

LatentGraphRAG runs Recursive Dense Retrieval (RDR; Anonymous, 2026) over two indices and returns one ranking of source documents:

  1. The document tree searches the documents with RDR's tree and global readout.
  2. The memory tree searches the memories with the same encoder, recursive update and readout; its children are selected by maximal marginal relevance.
  3. The memory readout is projected onto the documents that supplied the memories.
  4. The document view and the projected memory view are fused into one document ranking.

RDR's search strategies, readouts and encoder options are documented on the RDR project page.

Building an index

LatentGraphRAG(model, config=PAPER, **rdr_kwargs) takes an RDR checkpoint (path or model id) or any encoder object RDR's RecursiveRetriever accepts. Further keyword arguments (devices, batch sizes, dtype) go to RecursiveRetriever unchanged.

build(documents, inventory=None, groups=None, cache_dir=None, show_progress_bar=True) encodes the documents and the memories once and returns an LGRIndex:

ArgumentDescription
documentsdocument texts, or {document id: text}
inventorya MemoryInventory whose sources are document ids; None builds a documents-only index
groupsfor a chunked corpus, the document id of every chunk (see below)
cache_dirembedding caches, in documents/ and memories/ below it

The returned LGRIndex holds documents and memories (RDR dense indices), the inventory, and doc_of, the document id at every position of the document index. index.joint() builds the joint index of the ablation from the existing embeddings, without encoding anything again.

Chunked corpora

When documents are split into chunks, pass the chunks as documents and their document ids as groups (one id per chunk). The document tree then searches chunks, and a document scores the maximum over its chunks among the readout's top units. Inventory sources are document ids in this case, not chunk ids.

Searching

search(queries, index, k=10, view="D+M", instruction=None) returns one LGRResult per query. k=None returns every ranked document. instruction replaces the root instruction (default: RDR's multi-hop instruction).

The memory tree

Constructed units are short and often near-duplicates: the same fact as a triple and as a proposition, or the same relation extracted from several passages. The memory tree therefore selects each state's children by maximal marginal relevance instead of top score. A state takes the mmr_pool × branching best units not selected at earlier levels and greedily adds the unit that maximises λ · score − (1 − λ) · redundancy, where the redundancy is the largest dot product with a unit it has already picked. The first pick is the top-scoring unit.

Everything else is RDR's tree unchanged: one level at a time, units chosen at earlier levels are excluded, and a unit chosen by several parents becomes one child on its best path. The search is available on its own as MMRTreeSearch(depth, branching, lam, pool), a subclass of RDR's TreeSearch; bind(index) gives it the unit embeddings for the redundancy term. memory_mmr=False switches the memory tree to RDR's plain tree.

Projection and fusion

Projection turns the memory view into a document view. With projection="max" (the paper's choice), a document receives the largest score of the retrieved memories it supplied, and zero when none of them did:

Fusion combines views over the same document ids. With fusion="combmnz" (the paper's choice), a document scores the weighted sum of its view scores times the number of views that contain it. The paper weighs the document view with 1 and the memory view with 0.5. Readout scores are fused as they are, without normalisation: both views come from the same readout.
